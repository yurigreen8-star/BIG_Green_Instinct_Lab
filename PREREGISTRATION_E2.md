## 1. Среда E2

- Число участков: N = 30.
- Каталог измерений: **только FAST**. Шум r = 1, стоимость = 1.
- Бюджеты: **45** и **90**, исследуются отдельно.

Генеративная модель, независимая по участкам:

```
mu_i ~ N(0, 1)            начальные средние убеждений
s_i  ~ U(0.5, 2.0)        начальные дисперсии убеждений
q_i  ~ N(mu_i, s_i)       скрытая истинная величина
```

Начальный Belief:
```
mu[i]     = mu_i
sigma2[i] = s_i
known[i]  = False
```

Модель согласованная: агент знает те же распределения, из которых получена истина.

**Отличие от E1-A:** в E1-A было `mu_i = 0`. В E2 начальные средние случайны.
Числа E2 не сопоставимы напрямую с E1-A.

### 1.1. Повторные измерения

Все участки доступны на протяжении всего эпизода. **Повторные измерения
разрешены с первого шага.** Обязательный первый обход не требуется.
`known_mask` не используется для запрета повторных измерений; `known`
сохраняется как информационный признак.

Все политики работают при одинаковых ограничениях доступности.

### 1.2. Завершение эпизода

Эпизод завершается при исчерпании бюджета (стоимость каждого измерения = 1,
поэтому число измерений равно бюджету). Итоговый выбор — участок с
максимальным апостериорным средним.

## 2. Случайные потоки и воспроизводимость

Восемь независимых потоков через `np.random.SeedSequence(seed).spawn(8)`
с целочисленными идентификаторами:

| ID | Поток |
|---:|---|
| 0 | начальные параметры mu_i, s_i |
| 1 | истинные значения q_i |
| 2 | шум измерений (резерв; фактический шум через CRN-ключ) |
| 3 | разрешение ничьих C_OL |
| 4 | разрешение ничьих C_BS |
| 5 | разрешение ничьих Ratio |
| 6 | случайные решения MATCH |
| 7 | Monte Carlo оценка EVPI |

Строки в `SeedSequence` не передаются. Python `hash()` не используется.

### 2.1. CRN для шума измерений

Шум определяется устойчивым ключом `(seed, parcel_id, rep_index)`, где
`rep_index` — номер повторного измерения данного участка.

Реализация сохраняет существующий формат ключа среды v3.0:
```
key = f"{episode_seed}|{parcel_id}|{probe_type_id}|{rep_index}"
digest = blake2b(key.encode("utf-8"), digest_size=8)
noise_seed = int.from_bytes(digest, "little", signed=False)
```
В FAST-only среде `probe_type_id` постоянен, поэтому ключ эквивалентен
`(seed, parcel_id, rep_index)`. Формат сохранён для совместимости с v3.0.
`[ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ]`

Один и тот же зонд одного участка с тем же `rep_index` получает одинаковый
шум независимо от политики и порядка действий.

### 2.2. Общие случайные числа при сравнении

- Все политики на одном сценарии получают одинаковые mu_i, s_i, q_i и шумы.
- MC-выборки EVPI общие для всех политик одного сценария (поток 7).
- Броски MATCH общие для всех значений q при калибровке (§8).
- Потоки одной политики не зависят от числа действий другой политики.

## 3. Механизмы

### 3.1. C_OL — open-loop Curiosity (формула v3.0, не меняется)

Для каждого участка i:
```
u_i = sigma2_i / s_i          относительная неопределённость
n_i = 1 / (1 + v_i)           новизна, v_i — число прошлых посещений
A_i = u_i * n_i
I_i <- (1 - lambda) * I_i + lambda * A_i
lambda = 0.3
I_i(0) = A_i(0) = 1
```

`s_i` — **индивидуальная** начальная дисперсия участка. Общая константа
`sigma2_prior = 1.0` вместо массива начальных дисперсий не используется.

Порядок операций после каждого фактически выполненного измерения:
1. увеличить счётчик посещений измеренного участка;
2. пересчитать A для **всех** участков;
3. обновить I для **всех** участков, включая неизмеренные.

Предложение: участок с максимальным I. Ничьи — поток 3.

C_OL не получает: стоимость, бюджет, EVSI, состояние Ratio, таблицу Ratio,
истинные значения, значения наблюдений.

**Свойство open-loop:** апостериорная дисперсия не зависит от значения
наблюдения, поэтому мотивационное состояние и последовательность предложений
C_OL не зависят от q_i и o_i.

### 3.2. C_BS — closed-loop Curiosity (новый модуль `curiosity_bs.py`)

Начальное состояние:
```
A_i(0) = IG_i(0) = 0.5 * ln(1 + s_i / r)
I_i(0) = A_i(0)
lambda = 0.3
```

Для непосещённого участка A_i = IG_i.

После каждого фактически выполненного измерения участка i:

1. Сохранить Belief **до** измерения: `(mu_0, s_0)`.
2. Получить Belief **после**: `(mu_1, s_1)`.
3. Вычислить Bayesian Surprise:
```
BS_i = 0.5 * [ ln(s_0 / s_1) + (s_1 + (mu_1 - mu_0)^2) / s_0 - 1 ]
```
4. Увеличить счётчик: `v_i <- v_i + 1`.
5. Установить для измеренного участка: `A_i = BS_i / (1 + v_i)`.
6. Для остальных участков **сохранить ранее установленные A_j**.
7. Обновить интерес всех участков: `I_j <- (1-lambda)*I_j + lambda*A_j`.

**Правило сохранения A:** сохранённое A измеренного участка не пересчитывается
при измерении другого участка. Оно действует до следующего измерения самого
этого участка.

Значение наблюдения `o` напрямую в C_BS не передаётся: BS вычисляется из
разницы Belief до и после. C_BS обновляется одинаково независимо от того,
кто предложил действие — Curiosity или Ratio.

C_BS не получает: стоимость, бюджет, EVSI, состояние Ratio, оценки Ratio,
истинные значения.

Предложение: участок с максимальным I. Ничьи — поток 4.
Дополнительно возвращается **полное ранжирование** участков по I (нужно VETO).

### 3.3. Тождество для проверки BS

При r > 0 и s_0 > 0:
```
IG    = 0.5 * ln(1 + s_0/r)
kappa = s_0 / (s_0 + r)
z     = (o - mu_0) / sqrt(s_0 + r)

BS = IG + 0.5 * kappa * (z^2 - 1)
E[BS] = IG    при усреднении по корректному prior predictive
```

Используется как математический тест реализации. Предел r → 0 (вырожденный
posterior) отдельным граничным случаем; конечность BS в этом пределе не требуется.
Все проверки — при строго положительных дисперсиях.

### 3.4. Ratio

Аналитический EVSI для доступных FAST-зондов. Предложение:
```
p* = argmax_p EVSI(p)
```
Ничьи — поток 5.

Возвращает: выбранный зонд, его EVSI, таблицу EVSI всех доступных зондов,
EVSI первого предложения Curiosity (если передано).

Ratio **не получает** внутренние состояния Curiosity: `interest`,
`visit_count`, `last_surprise` и прочие. Оценка предложения Curiosity не
означает управления её мотивационным состоянием.

### 3.5. Coordinator

Получает: первое предложение Curiosity, её полное ранжирование, таблицу EVSI
от Ratio, режим арбитража. **Не получает** внутренние состояния Curiosity,
Environment, `theta_true`. **Не вычисляет EVSI самостоятельно.**

Обозначения: `z_C` — первое предложение Curiosity, `p*` — предложение Ratio,
`eps = 1e-12`, `rho = 0.5`.

**DOM:**
```
исполнить p*,  если EVSI(p*) > EVSI(z_C) + eps
иначе исполнить z_C
```

Условие возможного отличия DOM от RATIO_SOLO:
```
EVSI(p*) - EVSI(z_C) <= eps
```
Это **не** условие `max EVSI < eps`.

В FAST-only среде при одинаковой стоимости DOM структурно склонен
воспроизводить Ratio. Особенность не устраняется искусственно, тестируется
на каждом шаге и отражается в отчёте.

**OVR:**
```
исполнить z_C,  если EVSI(z_C) >= rho * EVSI(p*)
иначе исполнить p*
```

**VETO (разведочный):**
```
если EVSI(z_C) <= eps и существует участок с EVSI > eps:
    отклонить z_C, идти по ранжированию Curiosity
    исполнить первое предложение с EVSI > eps
если все EVSI <= eps:
    исполнить z_C
```
Ratio поставляет таблицу EVSI, но не выбирает действие вместо Curiosity.

VETO не входит в MATCH и не входит в основную семью сравнений (§7).

DOM не исключается из зарегистрированного семейства и статистики, даже если
его структурная эквивалентность Ratio очевидна.

## 5. Гипотезы

### H1. C_BS реактивна к наблюдениям (closed-loop)

**Предсказание:** последовательность действий C_BS_SOLO зависит от фактических
наблюдений, а не только от начальных параметров и счётчиков.

**Операционализация** `[ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ]`: для каждого сценария
строятся два варианта с одинаковыми mu_i, s_i, RNG политики и CRN-шумом,
но различными истинными значениями q_i (различные реализации потока 1).
Сравниваются последовательности выбранных участков C_BS_SOLO.

**Критерий:** доля сценариев, где последовательности различаются, **≥ 95%**.

**Разделение проверок:**
- pytest проверяет математическую и программную реактивность на специально
  сконструированных наблюдениях (детерминированный тест);
- эмпирическая проверка H1 проводится по описанной процедуре на
  подтверждающих seed.

Недостижение порога 95% — исследовательский результат, а не свидетельство
некорректности кода. Формула и параметры для прохождения H1 не меняются.

### H2. C_OL open-loop

**Предсказание:** при одинаковых mu_i, s_i, последовательности выполненных
участков и RNG ничьих изменение q_i и o_i **не меняет** мотивационное состояние
и последовательность предложений C_OL.

**Критерий:** побитовое совпадение последовательностей на всех проверяемых
сценариях (100%). Это математический инвариант, проверяемый pytest.

Диагностические величины, зависящие от наблюдений, не входят в мотивационное
состояние и не нарушают инвариант.

### H3. Различие мотивационных критериев

**Предсказание:** IG, EVSI и C_OL дают различные предпочтения участков.

**Критерий:** изолированный трёхсторонний пример (§9.3) воспроизводит
разные выборы; на случайных сценариях фиксируется доля шагов, где первые
предложения IG-политики, Ratio и C_OL попарно различаются.

Различие поведения **не** трактуется как доказательство самостоятельности
мотивационных механизмов. Величина описательная.

### H4. Координация против расписаний

**Предсказание:** содержательный арбитраж V даёт иной результат, чем случайное
вмешательство с той же фактической частотой замен (MATCH).

**Критерий:** первичный контраст Δ_sched (§7.1) по EVPI(b_T), парные
доверительные интервалы, Holm по семье из 16, TOST с δ = 0.01.

Превосходство V **не** формулируется заранее как установленный факт.
Отсутствие значимости не трактуется как доказательство эквивалентности;
эквивалентность оценивается отдельно через TOST.

### H5. Структурная склонность DOM к Ratio

**Предсказание:** в FAST-only среде при равной стоимости DOM почти всегда
исполняет предложение Ratio.

**Критерий:** описательная величина — доля шагов, где исполненное действие
DOM отличается от действия RATIO_SOLO, и число шагов с
`EVSI(p*) - EVSI(z_C) <= eps`. Порог не задаётся; результат описывается.

## 6. Метрики

### 6.1. Первичная

```
EVPI(b_T) = E[ max_i q_i | b_T ] - max_i E[ q_i | b_T ]
```

Monte Carlo, **N = 40000** выборок, поток 7, общие выборки для всех политик
одного сценария. Сохраняются: оценка, стандартная ошибка MC, число выборок.
Пакетная генерация для ограничения памяти.

### 6.2. Вторичные (описательные, не первичные)

| Метрика | Определение | Единицы |
|---|---|---|
| regret | `q[true_best] - q[chosen]` | единицы q |
| PCS | `chosen == true_best` | доля |
| budget_used | сумма стоимостей | кредиты |
| n_probes | число выполненных измерений | штуки |
| n_unique_first_n | число уникальных участков в первых n шагах | штуки |
| n_repeats | `n_probes - n_unique` | штуки |
| Spearman(s_i, repeats_i) | корреляция рангов по участкам | безразмерная |
| энтропия посещений | `-Σ p_i ln p_i`, `p_i = visits_i / n_probes` | наты |
| Gini посещений | по вектору из 30 значений, включая нули | безразмерная |
| доля шагов `max EVSI < 1e-12` | диагностика вырожденности | % от всех шагов |

### 6.3. Метрики вмешательства — различать строго

| Метрика | Определение |
|---|---|
| доля выборов Ratio | MATCH/арбитр выбрал предложение Ratio / все шаги, % |
| **фактическая доля замен** | исполненное действие ≠ первое предложение Curiosity / все шаги, % |
| доля действий Ratio | исполнено предложение Ratio / все шаги, % |

Если Ratio и Curiosity предложили один участок, **замены нет**, даже когда
арбитр формально выбрал Ratio. Подмена одной метрики другой запрещена.

В сырых данных сохраняются все три счётчика отдельно.

## 7. Статистический план

### 7.1. Первичные контрасты

Для каждой из четырёх основных V и каждого бюджета:

```
Delta_sched(V) = EVPI(V) - EVPI(MATCH(V))
Delta_ratio(V) = EVPI(V) - EVPI(RATIO_SOLO)
```

`[ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ]` Знак: **отрицательное значение означает, что V лучше**
(меньше остаточная неопределённость решения). Направления фиксируются здесь
и не переопределяются после получения результатов.

### 7.2. Семейство сравнений

**16 первичных сравнений** `[ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ]`:
```
4 основные V  ×  2 бюджета (45, 90)  ×  2 контраста (sched, ratio)  =  16
```

Единая процедура **Holm** применяется ко всем 16 одновременно, один раз.
VETO-группы в это семейство не входят.

### 7.3. Методы

- Парные разности по одинаковым сценариям; парность проверяется.
- Средняя парная разность, SD парных разностей, число сценариев.
- Парный t-интервал, 95%.
- Парный bootstrap по сценариям, 95%, число ресэмплов фиксируется в конфигурации.
- Двусторонний Wilcoxon по парным данным — дополнительный анализ.
- Holm по семье из 16 для первичных проверок превосходства.
- **TOST** с δ = 0.01 по EVPI для эквивалентности, 90% CI. Применяется к тем же
  16 контрастам как отдельное зарегистрированное семейство эквивалентности
  с собственной поправкой Holm. `[ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ]`

Скорректированное p не может быть меньше исходного. Тест Holm:
```
p = [0.003984, 0.7399, 0.003984, 0.7399, 0.003984]
ожидаемый результат = [0.0199, 1.0, 0.0199, 1.0, 0.0199], допуск 1e-4
```

`p > 0.05` не интерпретируется как доказательство отсутствия различий.

### 7.4. Размер выборки

Подтверждающая выборка: **1000 сценариев**, сиды 51000–51999 (§10).

После проектной фазы обязательно рассчитывается достижимая мощность:
```
n ≈ ((z_{1-alpha/2} + z_{0.8}) * SD_paired / Delta)^2
```
Для минимального p в семье из 16 эффективный уровень alpha' = 0.05/16 = 0.003125,
двусторонний z ≈ 3.011; z_{0.8} ≈ 0.8416.

Если при SD парных разностей из проектной фазы требуемая мощность при
Delta = 0.01 недостижима на 1000 сценариях, это фиксируется в отчёте,
и автор принимает решение о расширении выборки.
**Уменьшать выборку из-за благоприятного предварительного результата запрещено.**

### 7.5. Что не является первичным

regret, PCS, Spearman, энтропия, Gini, доли замен, VETO-группы, а также
любые показатели, не входящие в §7.1–7.2, анализируются как разведочные
и не могут служить основанием для формулировок о подтверждении гипотез.

## 8. Калибровка MATCH

MATCH сравнивается с соответствующим V по **фактической доле замен**, а не
по вероятности выбора Ratio.

```
q      = P(выбрать Ratio)
r(q)   = фактическая доля замен предложения Curiosity
```

Это разные величины. Замена происходит только когда исполненное действие
отличается от первого предложения Curiosity.

### 8.1. Целевые частоты

На проектной фазе (сиды 50000–50099, оба бюджета) измеряется фактическая доля
замен r_target для четырёх основных V.

Эталоны автора для сверки:

| Группа | Бюджет 45 | Бюджет 90 |
|---|---:|---:|
| C_OL + DOM | 0.91 | 0.72 |
| C_BS + DOM | 0.89 | 0.71 |
| C_OL + OVR | 0.91 | 0.88 |
| C_BS + OVR | 0.93 | 0.91 |

Допуск сверки ±0.05. При расхождении параметры **не подгоняются**,
расхождение сообщается автору.

### 8.2. Сеточный поиск q

1. Сетка q от 0 до 1 с шагом 0.01.
2. Броски MATCH общие для всех q в одном сценарии на одном шаге; генерация
   случайного числа **не зависит от q** (поток 6, CRN).
3. Для каждого q измеряется фактическая доля замен.
4. Выбирается q с минимальным `|r_MATCH(q) - r_target|`.
5. При равенстве расхождений выбирается **меньшее q**.
6. Бисекция без предварительной проверки монотонности r(q) не применяется.
7. Допускается уточнение сетки около минимума с шагом 0.001.
8. Формулы Curiosity и Ratio для улучшения совпадения не меняются.

### 8.3. Содержимое `q_V.json`

Для каждой группы и каждого бюджета: тип Curiosity, тип Coordinator, бюджет,
r_target, выбранное q, фактическая доля замен MATCH на калибровочных seed,
абсолютное расхождение, список seed, шаг сетки, конфигурация RNG, версия кода
и хеш коммита.

В подтверждающей фазе зафиксированные q применяются **без повторной калибровки**.

### 8.4. Что MATCH не делает

MATCH не читает внутреннее состояние Curiosity и не выбирает моменты
вмешательства на основании её интереса.

Тест MATCH не требует равенства q и фактической доли замен. Проверяется
отдельно: частота выбора Ratio соответствует q с учётом биномиальной
случайности; фактическая доля замен измеряется независимо; результат
калибровки сопоставляется с r_target соответствующего V.

## 9. Обязательные тесты до экспериментальных прогонов

### 9.1. Математические

1. BS через KL совпадает с прямой формулой.
2. BS через KL совпадает с `IG + 0.5*kappa*(z^2-1)`, допуск 1e-9.
3. MC проверка `E[BS] = IG` для сетки `s_0 ∈ {0.5,1,2}`, `r ∈ {0.25,1,4}`;
   критерий через стандартную ошибку MC, не произвольный фиксированный допуск.
4. Апостериорные среднее и дисперсия соответствуют аналитическим формулам.
5. EVSI на эталонных случаях и граничных значениях.
6. Численная устойчивость при строго положительных дисперсиях.
7. Ratio выбирает максимум EVSI.

### 9.2. Поведенческие

1. C_OL open-loop (H2): изменение истинных значений не меняет состояние и предложения.
2. C_BS closed-loop: сконструированный тест, где изменение результата измерения
   меняет BS, сохранённое A, внутреннее I и последующее предложение.
3. Сохранение A_i между измерениями других участков.
4. Обновление I всех участков после каждого измерения. Не требовать изменения
   каждого числа: EMA может оставлять значение неизменным, если оно совпадает с целевым.
5. C_BS обновляется после действия Ratio так же, как после действия Curiosity.
6. MATCH не имеет доступа к внутренним состояниям Curiosity.
7. Фактическая доля замен MATCH измеряется отдельно от q.
8. Coordinator выполняет зарегистрированное правило и не вычисляет EVSI.
9. `theta_true` недоступен политикам и Coordinator.
10. Повторный запуск одного сценария даёт идентичный результат.
11. CRN даёт одинаковый шум для одинаковых `(seed, parcel_id, rep_index)`.

### 9.3. Тест трёх стратегий

Изолированный пример: три участка, каждый после одного FAST-измерения, r = 1.

| Участок | Исходная дисперсия s | Текущее среднее mu |
|---|---:|---:|
| A | 2.0 | −2.0 |
| B | 1.0 | 0.9 |
| C | 0.5 | 1.0 |

Ожидаемые выборы:
- `B_IG_FAST` → A
- Ratio по EVSI → B
- C_OL → C
- DOM переопределяет C в пользу B
- OVR(0.5) принимает C, поскольку `EVSI(C) >= 0.5 * EVSI(B)`
- VETO принимает C

Контрольные значения после одного измерения:
```
IG(A)     ≈ 0.255
EVSI(B)   ≈ 0.118
EVSI(C)   ≈ 0.072
C_OL(A)   ≈ 0.167
C_OL(B)   ≈ 0.250
C_OL(C)   ≈ 0.333
```

Для C_OL последовательность измерений строго A → B → C; начальное I = 1;
после каждого измерения пересчитываются A всех участков и обновляются все I.
Проверяется фактическое ранжирование I, а не только значения A.

Допуск численных сравнений 1e-3.

### 9.4. DOM и RATIO_SOLO

На каждом шаге проверяется `EVSI(p*) > EVSI(z_C) + eps` и соответствующее
решение Coordinator. Расхождение исполненных действий допускается при
`EVSI(p*) - EVSI(z_C) <= eps`. Условие `max EVSI < eps` вместо этого не используется.

При идентичной истории действий траектории и результаты совпадают.
При различии сохраняются конкретные шаги и причины. Тождество конечного
regret без тождества истории действий не требуется.

### 9.5. Статистические и отчётные

- Единая функция Holm для всего зарегистрированного семейства.
- Тест Holm на векторе из §7.3.
- Скорректированное p ≥ исходного.
- Unit-тесты TOST и парных CI на синтетических данных.
- Проверка парности сценариев.
- Консольный отчёт и JSON содержат одинаковые численные результаты.
- Блок парных сравнений не пуст без пояснения.
- Все метрики имеют однозначные определения и единицы; сырые значения доступны.
